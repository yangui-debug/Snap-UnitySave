# 新版桥口近战配置说明

适用场景：`Assets/20261012-PVE守关敌万军/20261012-PVE收关敌万军.unity`。

## 已接入的对象

- `蓝木盾卫士` 总父物体：新增 `BlueShieldAdvance`，只管理本组蓝盾。旧 `RightBridgeMeleeDirector` 组件已停用、隐藏，旧 Director 和 Unit 源码保持原样，没有删除。
- 场景中 7 个红方生成器：新增 `RedMeleeSpawnSetup`。原生成器在实例化后调用它，为红方近战安装 `RedMeleeSelf`，按值复制本兵营配置。兵种、生成频率、喷射、分桥和桥路点分配沿用原逻辑。
- 红兵等候、补位、来源闪白配置在自己的 `RedMeleeSelf.settings`；批量默认值在对应红方兵营的 `RedMeleeSpawnSetup.redSettings`。击退距离、时长、轴向和僵直回归红兵原 `SoldierHealth`，不再由独立交战组件执行击退。蓝方对象没有安装红方控制组件。
- 原 `SoldierHealth`、`SoldierAIMovement`、`SoldierSpawner` 只增加新版接入入口，兼容旧入口；攻击事件、伤害、箭矢和死亡表现保持原实现。

## 需要你接线的一处

在右桥口自行放置带 Collider 的空物体，勾选 **Is Trigger**，把 Collider 拖到 `蓝木盾卫士 → BlueShieldAdvance → Detection Trigger`。建议使用 BoxCollider，可直接调整它的位置、旋转和 Size；本脚本支持 Box/Sphere/Capsule 检测体。未拖入、触发器被禁用或未勾 Is Trigger 时，新版蓝盾控制不生效。没有创建任何永久测试触发器。

检测器内只统计存活士兵，多个 Collider 只计一人；红方计 `Enemy Faction`，蓝方计 Blue 阵营。按你的要求，人数比较使用检测器实际覆盖到的蓝兵数量，因此请让检测体覆盖预期参与比较的蓝方队列。人数刷新默认 0.1 秒一次，实际移动仍逐物理帧执行。

## 蓝盾配置

`First Row` 留空时，首次发现红兵后沿 `Forward Axis` 逐列选择没有更前方友军的盾兵，支持斜排。`First Row Depth=0.8` 米为纵向同排容差，`First Row Lane Half Width=0.7` 米为同列横向检测半宽；应略大于前后排错列量，小于相邻列间距。需要精确指定时，拖入第一排各自实际启用的攻击组件，通常是模型 `Ironguard` 上的 `SoldierAnimationController`。

每次有限推进独立抽取 `Advance Distance`（默认 0.8–1.5 米），以 `Advance Speed`（默认 1.6 米/秒）朝有效红方目标移动。到随机路程、停止距离、碰撞体或移动边界时停止。原目标被击退超过阈值、死亡并出现新目标时，可再次有限跟进；原位不随补位更新，总位移始终受硬边界约束。

`Keep Lane When Blocked` 默认开启：多名盾兵锁定同一个中间目标时，斜向靠近容易向同排友军收拢。斜向受阻后先尝试沿列线前进；斜排胶囊贴靠时，再投影掉朝友军体内的速度，沿友军接触面小幅避让。候选位移均重新执行碰撞和固定边界检查；不绕过敌人、不越过目标，也不改变击退或退守方向。关闭此选项恢复原先只尝试直达目标方向的行为。

`Max Forward=1.5` 米、`Max Backward=1` 米、`Max Lateral=0.4` 米分别限制前、后、横向偏移。后退硬上限用于受击；主动退守目的地为原位。蓝盾原位记录为单兵容器固定本地坐标，跟随原有 Timeline 编组调动；不移动整个编队，也不直接移动会被 Animator 写回的模型节点。`Control Center / Size` 是允许新增控制的右桥世界区域；编组被 Timeline 调往左桥后停止接管。

开启 `Retreat When Outnumbered` 时，检测区红兵人数大于蓝兵人数，每个第一排蓝盾独立等待 `Retreat Delay`（默认 0.2–0.9 秒），再以 `Retreat Speed`（默认 0.65 米/秒）慢慢回原位。等待中停止推进；人数条件失效则取消本次退守等待。受击优先于推进和退守，碰撞阻挡时不会强行穿过友军归位。没有目标时不因空位继续前进。

## 红兵配置

默认只在右桥世界区域 `Center=(9,1,-13), Size=(10,8,14)` 生效，方向为 Z 负轴；左桥、远程、其他场景不接管。排队时为前兵保留至少 `Retreat Space=2` 米净退路；前兵原 `SoldierHealth.击退距离` 更大时取更大值，再加双方占位半径以及后排一帧刹停余量。`Front Separation=0.6` 米避免斜列同排士兵互相当作前排；`Lane Padding` 调节同列横向余量。

前路开放或原目标死亡后，单兵重新判断目标与占位，独立等待 `Refill Delay=0.18–0.55` 秒；这只限制补位移动，不关闭原攻击。通路再次堵塞、受击、目标切换、失活时取消旧计时和空位租约。同一未来空位互斥；死亡单位立即失去活兵占位资格。友军登记表只共享可查询信息，不替红兵驱动移动，每个物理帧只筛选一次活动红兵以减少全场扫描。

移动仲裁固定为 **死亡 ＞ 受击击退/僵直 ＞ 战斗补位/跟进 ＞ 常规寻路**。平时红兵交战组件只向原移动脚本返回速度；受击期间由原 `SoldierHealth` 协程执行击退，移动脚本清除自主水平速度，保留重力、碰撞和 Agent 位置同步。结束后按当前目标重算，不恢复旧方向。`RedMeleeSelf` 不再保存击退速度、计时或提供独立 BeginHit 接口。

**击退唯一调节入口：生成器实际引用的原始“红补兵”上的 `SoldierHealth → 击退距离 / 击退时长 / 击退轴向控制 / 僵直停顿时间`。** 近战和远程共用这里的距离。原生成器通过 Instantiate 复制原始模板，所以播放中修改该模板的击退距离，之后新生成的克隆体会继承修改值，无需额外同步脚本；已经存在的克隆体不会被追溯覆盖。只调整该项不影响独立来源闪白。

受击协程按实际帧时间分配原距离，补齐最后一帧剩余路程，避免击退时长短于一帧时整次被跳过。碰撞检测仍保留，不通过穿过后排或墙体强行补足距离；后排按前兵配置提前留空间。

闪白通过明确的 `SoldierDamageSource` 区分 Melee、Ranged、Unspecified。近战默认持续 0.08 秒、自发光原强度的 0.25 倍；远程默认保持原设置，可独立关闭或改时长、倍率。未指定来源和原独立加速闪红流程保持原行为；白模替换本身只有启用和时长，不能通过自发光倍率调透明程度。伤害、击退、缩放和死亡不随闪白开关关闭。

## 调参与关闭

新增可配置字段有中文分组、详细中文 Tooltip 和代码注释。蓝盾速度、距离、随机时间、检测层等可公开设置；红兵生成默认值在红方兵营设置，已生成红兵拥有自己的独立配置，修改兵营不会追溯改写现有红兵。碰撞层、半径及安全间隙支持播放中调参。

蓝盾关闭 `Enable Behaviour`；红方关闭相应生成器配置的 `Enabled`（影响随后生成的红兵），已生成者可关闭自身设置的 `Enabled`。关闭不瞬移归位，新受击恢复原入口。Gizmos 随对应总开关、排队功能和蓝盾 `Show Gizmos` 显隐，选中物体查看范围。

旧版组件为避免 Inspector 混用已隐藏。需要查看历史代码时直接打开 `RightBridgeMeleeDirector.cs`、`RightBridgeMeleeUnit.cs`；不要同时启用旧版和新版。

## 验证方式

菜单 `Tools → 新版桥口近战 → 运行20秒场景验证`：拒绝覆盖未保存场景或接管现有播放；只在本次播放临时接入一个测试检测体，不保存场景，结束退出播放。结果写入 `Temp/MeleeV2-results.json`，10 秒游戏渲染截图写入 `Temp/MeleeV2_10s.png`。隔离断言验证优先级、排队、预留互斥、来源闪白、蓝盾有限推进、独立退守等待、死亡补位、关闭和离区释放；实际场景同时统计接入人数、状态和边界。

正式保存的场景仍需你拖入自己放置的触发器；它的覆盖范围会影响人数比较与退守时机。

2026-10-15 最终复测：26 项隔离断言全部通过（包含斜列逐列识别前排）；目标场景实际播放 20 秒，接入 32 名蓝盾、66 名进入右桥区域的红兵。观察到红兵等候、随机补位、受击后退/僵直，蓝盾有限推进、随机退守等待、退回原位与离开右桥交还控制。最大前进偏移 1.5 米，边界违规 0，左桥/远程误控 0，旧管理器活动计数 0，本轮捕获运行错误 0。编译检查 0 错误，完整构建有 58 个项目既有警告。

验收时发现原场景自动播放的 Timeline 曾停在 0 秒，前一轮同时出现 Unity Recorder 自身空引用错误。最终验收仅在播放期间对本应自动播放且停在 0 秒的 Director 调用 Play 恢复，未改 Recorder 设置、Timeline 资源或正式场景配置。结果副本见 `新版桥口近战验收结果.json`；截图为临时测试检测器接入时的游戏渲染结果，不能代表你后续自行设置的检测器范围。

后续“手动指定两侧共 8 人、只有一侧前进”问题已复现：8 个手动引用都正确且已识别为第一排；停住的一侧因斜向追同一个中间目标，被同排碰撞体阻挡，裁剪后的实际速度为零。新增上述列线/接触面备用推进后，使用用户当前未保存的 8 人接线及实际触发器直接播放复测，8 秒时 8 人均观察到前进，前进偏移约 0.7–1.5 米；30 项隔离规则验证通过。过程没有保存或重新加载用户场景。详细记录见 `八名首排盾兵推进修正验收.json`。

红兵击退回归原组件后的验证见 `原红补兵击退回归验收.json`：通过真正 SoldierSpawner 在播放中生成克隆，原始模板改为 0.25 米、0.75 米和 0 米时，新克隆正确继承并实际后退对应距离；近战与远程同为 0.75 米。短于一帧的击退时长仍执行路程；墙体阻挡时位移截短；禁用生命组件会停止旧击退，重新启用后可再次受击。前排完成约 2 米后退，后排保持等候、不向前推挤。最终场景播放观察到 59 名普通生成红兵的实际受击位移和 123 名红兵等候，7 项运行时检查与 30 项规则断言通过，编译 0 错误。正式场景文件、蓝方脚本、生成器和生成接入脚本经哈希检查均未改变，闪白配置及来源判断保留。
